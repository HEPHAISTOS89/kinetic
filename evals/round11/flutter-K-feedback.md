# Kinetic v2.1 — candid feedback from this run (Fernhill, studio, create D2)

1. **Expression level vs the dealt engine conflict.** The `type-index` engine asks for 44–64pt display words; a high-stakes brief caps the level at 2–3 (display max 40/48). `validate` then flags K07 (C) whatever you do. The deal should respect the expression cap (or scale the engine's ramp to it), or the engine should say what to do at level ≤ 3.
2. **The clarity measure and the critics disagree on words — and on voids.** `kinetic clarity` estimated ~48 words for the home; all three critics hand-counted ~85–88 against the KDL's own 60. Worse: clarity rewards empty space (my fold-push raised it to 87) while the critics' layout floor penalises the same space as "voids in short states". Pixel-word estimation is off by ~2× on this kind of screen; the two signals pulled the design in opposite directions for a whole loop.
3. **Rows-under-a-sticky-bar vs voids is an unsolvable pair of floors as written.** layout.md §3b demands the fold fall on space *and* forbids voids >130pt, with no guidance for a scrolling home whose content length varies by state. Critics capped layout_craft at 3 in all three loops for one or the other. The knowledge needs the actual pattern (e.g. "peek the next row's title under the bar" or a continuation line) rather than two prohibitions.
4. **"Never ship fixes nobody judged" + max 3 loops = the last panel's consensus can't be acted on.** Loop 3's panel found a regression introduced by loop 2's own consensus fix (fold push). The protocol forbids a 4th loop and forbids fixing after the final panel, so the regression ships. A "one guarded fix + targeted re-check" exit would help.
5. **The `kinetic clarity` "loud colour areas" heuristic punished the correct emergency design.** An oxblood field + an oxblood filled call button scored 69 ("2 loud areas"), i.e. "cluttered", for a screen with ~35 words. I had to repaint the light emergency field as a pale wash to pass — arguably fine, but the tool drove a severity-colour decision.
6. **Pinned components not recognised by K21 by name.** A `pinned: true` component only counted once `reading_order` used its exact id (`emergency-line`), not the requirement's element phrase (`emergency line`). The K21 message ("is #6 in reading order") doesn't hint at the id/phrase mismatch.
7. **Engine slots that don't fit a household-sized home.** type-index ships "native search" and a "scrub the right edge" live thing; for 1–3 animals both are chrome. The protocol only allows redraws of type/palette/motion slots — there's no sanctioned way to drop an engine's shell/live-thing parts, so I did it in a fusion and explained it in `because`.
8. **Critics can't judge what the gallery can't render.** Two loops of native_fidelity = 3 asked for the iOS action sheet / Android dialog, which only appear after a tap; the studio has no convention for rendering transient surfaces (and the flutter.md golden gotchas only partly cover it). A "transient states" entry type in the gallery guidance would close this.
9. **Generated export ignores width axes sensibly but emits `FontVariation('wdth', 75)`** for a static DIN Condensed font — harmless but misleading in a generated token file.
10. **Button labels render as Ahem boxes in goldens** unless `fontFamily` is set on `ButtonStyle.textStyle` — documented in flutter.md, but only as a gotcha at the end; it cost a render cycle and should sit in the code module's first checklist.
11. **Small engine/path friction.** `kinetic contrast` takes two positional args but zsh `$p` word-splitting silently failed in a loop; the KROOT path with spaces made every engine call brittle (a wrapper script was the only sane way). `deal --redraw` works well; `panel --renders` stamping is a nice touch.
12. **Priors/D34 scan noise.** `scan` flags the dark-mode `on-field` (#F2EAD3, a text colour) and `surface-2` as "cream/parchment ground" — roles that aren't grounds. It's info-tier, but it reads as a ground judgement on text ink.
13. **Studio cost.** 3 directors + rival + 3 editors + 9 critics on one home screen; critics re-derive the same floors every loop. Critic JSONs must be saved verbatim by the lead (no write access), which costs a lot of tokens to retype — letting critics write their own file (or the panel read their text) would be cheaper and safer.
