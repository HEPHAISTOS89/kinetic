# Kinetic v1.8 — candid feedback log (Plot 42, studio, create, D2)

1. **Studio vs deal count mismatch.** The router says `kinetic deal --options 2`, the studio protocol step 1 says `kinetic deal --brief-file` (default count unclear), and the director agent file says "the three dealt options" / "develop all three". With an authored A + 2 dealt challengers, the agent file's wording ("If there is none, say so and stop: directions are dealt, not imagined") is awkward for director 1, who must develop an *authored* direction that is not in deal.json. I had to override it in the prompt.
2. **Fusion vs K29.** kinetic-direct §1.3 says "A fusion is marked `source: author`", but the validator then reports K29 "2 directions marked `source: author`" when the authored A is kept as a separate record. I used `source: fusion` (accepted silently — is that a recognised value?). The doc should say whether the fusion replaces A or sits beside it.
3. **`kinetic init` destroys nothing but its skeleton orders `idea` before `directions`**, while the think skill tells you to fill product/thesis/inventory first; easy to lose the `idea` block when splicing (I did once). Minor.
4. **Viability rule vs the developed scores.** Both dealt challengers came back with usability 3 from their own directors, so by §4 only the authored direction was viable — the rule as written pushes toward the author's prior unless the lead fuses. The fusion path (A voice + C engine) is what made the deal useful; the docs could say this outright.
5. **Font bundling knowledge is in the stack file only.** All three directors worried about `.ttc` loading because they were not pointed at `knowledge/stacks/flutter.md §Bundling` / `kinetic font split`. The director agent's reading list should include it (or the deal output should say "bundle with `kinetic font split`").
6. **Dealt palette contrast.** Option 1's amber accent #B06016 was 2.6:1 on its own dealt field #0F3D2E — the deal can hand out an accent that fails on its field; director 2 had to derive another colour.
7. **Dealt motion vs thesis.** Option 2's "Lively" pop spring (damping 0.65) contradicted a thesis written before the deal ("nothing bounces"). The deal weights palette by brief tone but apparently not motion.
8. **K24 achromatic accent.** For a design whose action is the field colour (creosote button with chalk text), the validator suggests declaring `strategy: monochrome` — fine, but the dealt/authored palette had no accent concept separate from the field, which the KDL roles model forces (accent/on-accent required).
9. **`kinetic scan` D34 false positive.** It flags `#EDEBE4` as a "cream/parchment ground" three times, but in this KDL it is `on-field` (chalk *text* on a dark door), not a ground. The check reads hex values, not roles.
10. **D13 hue-family budget fights the brief's own world.** Water (blue), brass (your tap/plot) and an ochre deadline are three meanings on this site; adding a season role pushed the validator to "3 saturated hue families exceed the budget". I had to reference `KColors.dark.danger` from code instead of declaring an honest role — the budget pushes toward hiding colours from the KDL rather than toward fewer meanings.
11. **Clarity vs critics pull in opposite directions.** Loop-1 critics (all three) asked to carry the vocabulary into the first viewport (rota as chalk initials on the door); doing so dropped `kinetic clarity` on home from 84 to 78 because day names + initials count as words. The clarity heuristic counts labels in a drawn object (plan tags, rota cells) the same as prose; the protocol gives no rule for which wins.
12. **Clarity on sheet renders** counts the dimmed home behind the sheet (log-sheet 67), so a clean sheet scores as cluttered. A scrim-aware measure (or ignoring dimmed regions) would help.
13. **Editor cut list was strong** (12 ranked cuts, each with a "loses:" line) — the most directly useful agent output; but two cuts (delete plan legend → "chalk 42 inside the plot") assumed geometry that can't hold a 13pt label; it doesn't see the render's scale.
14. **The golden gotcha about button text styles (Ahem boxes)** is documented in the stack file, but the exported `KType` styles have no fontFamily, so *every* `ButtonStyle.textStyle: KType.x` renders as boxes. The exporter could emit a helper (`KType.ui(context, style)`) or the theme could set button text themes.
15. **`kinetic clarity` is slow (~60–90 s for 32 renders) and very sensitive to non-text pixels.** Removing two 4%-alpha door seams, or moving the plan 8pt, swung home from 81 to 72 (words 51→61, "text sizes" 6→7 → the text_sizes part drops from 33 to 0, a cliff). Dark renders score 4–8 points lower than identical light ones. A score this jumpy shouldn't hard-block `ship` at <70.
16. **Critics misread renders and the panel cannot correct it.** The loop-3 product critic scored native_fidelity 3 partly on "iOS uses a Material BottomNavigationBar" — the code is a CupertinoTabBar. The protocol says "never edit a critique; disagree in `because`", but the score engine still takes the median, and there is no field in the panel/score to attach the lead's rebuttal.
17. **Loop-to-loop panels drift.** Loop 1 and loop 2 both had a median mean of 3.89; loop 3 came in at 3.78 after fixing loop-2 consensus items (new critics found new things). With fresh critics each loop, "stop when two loops don't raise the median mean" mostly measures critic variance, not design progress.
18. **Clarity budget vs. a hero that is a labelled drawing.** knowledge/clarity.md says hero ≤ 45 words, but the plan is the answer *and* needs words on every mark (D31: no legends). The two rules collide; there is no allowance for labels inside a vocabulary drawing.
19. **Agents reported the API-limit pause oddly:** the coordinator's resume note said "you were launching the loop-1 panel" when loop 1 was already complete — the studio files in `.kinetic/studio/loopN/` were what made the true state recoverable. (Good: the audit trail works as a resume point.)
20. **`kinetic score` verdict stays ITERATE at judged mean 3.78** with integrity/states/a11y/motion at 100; the "next" list repeats critic fixes that contradict each other across critics (e.g. "fold the rota into the plan" vs "write the rota as full names").
